# Welcome Travel · разведка идей контента в Instagram

Telegram-бот, который каждый день отслеживает выбранные Instagram-аккаунты (турагентства, отели, цветочные магазины — любые ниши), находит публикации, сработавшие **заметно лучше обычного для этого аккаунта**, разбирает их и предлагает, как применить приём для Welcome Travel.

## Как это работает

1. **Сбор данных:** раз в день бот забирает последние публикации каждого аккаунта и сохраняет метрики в SQLite (с историей снимков, чтобы видеть прирост).
2. **Отбор:**
   - Reels сравниваются с Reels по просмотрам, фото и карусели — с фото и каруселями по лайкам и комментариям (если лайки скрыты — только по комментариям). Разные метрики не смешиваются.
   - База сравнения — **медиана** последних 30 «созревших» публикаций того же типа (старше 48 ч). Медиана устойчива к редким вирусным роликам.
   - 🔥 **Выброс:** публикация старше 48 ч, набравшая ≥ 3× медианы (обычно 5 тыс., у этой 50 тыс. — значит ×10).
   - 🚀 **Быстрый рост:** публикация младше 72 ч, которая уже набрала ≥ 1,5× обычного итогового результата.
   - Отсекаются мелкие числа (меньше 1000 просмотров, меньше 50 лайков с комментариями) и аккаунты, у которых меньше 6 публикаций для сравнения.
   - От одного аккаунта — не больше 2 примеров в день. Каждая публикация отправляется только один раз.
3. **Разбор (Claude):** из ролика вырезаются кадры (5 кадров первых 3,5 секунд, чтобы разобрать хук, и 5 кадров по остальной части), которые вместе с подписью и цифрами отправляются модели. Ответ: формат, начало, сюжет, подача, **гипотезы** причин успеха (так и подписаны) и конкретная идея для Welcome Travel: хук, кадры, CTA. Примеры, которые плохо подходят турагентству (оценка ниже 3 из 5), отсеиваются.
4. **Telegram:** в сообщении есть ссылка, все доступные показатели и честная пометка «нет данных» там, где данных нет. Под ним кнопки:
   - ✍️ **Написать сценарий** → выбрать язык (русский или казахский) → описать тур → готовая раскадровка с подписью.
   - 💾 **Сохранить идею** → попадает в `/ideas`.
   - 👎 **Неинтересно** → учитывается в следующих разборах.

## Откуда брать данные Instagram: варианты, ограничения, стоимость

| | **Instagram Graph API — Business Discovery** (по умолчанию) | **Apify** (сторонний парсер) |
|---|---|---|
| Надёжность | Официальный API Meta, стабильный | Неофициальный сбор данных, иногда ломается при изменениях Instagram |
| Чьи аккаунты | Только **бизнес- и авторские** аккаунты | Любые открытые профили |
| Просмотры Reels | ✅ `view_count` | ✅ `videoPlayCount` (обычно) |
| Лайки | ✅, если владелец их не скрыл | ✅, если не скрыты |
| Комментарии | ✅ | ✅ |
| Подписчики | ✅ | не запрашиваются (для экономии) |
| Видео для разбора кадров | ✅ ссылка `media_url` (у части роликов с лицензионной музыкой её нет — тогда разбор идёт по обложке, и бот это пишет) | ✅ `videoUrl` |
| Сохранения, репосты, охват, удержание | ❌ недоступны для чужих аккаунтов | ❌ |
| Стоимость | **Бесплатно** | Оплата за каждую публикацию: ориентир $1,5–2,7 за 1000 (смотрите актуальную цену на странице актора). 5 аккаунтов × 30 постов в день ≈ 4 500 в месяц ≈ **$7–12 в месяц**; при `POSTS_PER_ACCOUNT=12` после первого запуска — примерно в 2,5 раза дешевле. Бесплатные $5 в месяц у Apify покрывают тестовый период. |
| Правила | Разрешено Meta | Против правил Instagram (сбор данных без API); риски ложатся на поставщика парсера, но стабильность не гарантирована |

**Рекомендация:** начать с Graph API (бесплатно и официально). Для аккаунтов, которые не являются бизнес- или авторскими, бот на `/check` покажет понятную ошибку. Им можно поставить `source: apify` в `accounts.yaml` или добавить командой `/add username ниша apify`.

**Чего нельзя получить ни одним способом:** сохранения, репосты, охват, удержание, источник трафика, рекламное продвижение у чужих публикаций. Если всплеск вызван рекламой или коллаборацией, мы этого не увидим, поэтому причины успеха помечаются как гипотезы. Звук и речь в роликах пока не анализируются; это можно добавить позже через распознавание речи.

**Claude API (разбор и сценарии):** модель `claude-opus-5-5` ($4 за 1M входных и $20 за 1M выходных токенов). Один разбор (10 кадров, подпись и ответ) стоит примерно **$0,05–0,12**, сценарий — около **$0,03–0,06**. Анализируются только отобранные кандидаты: не больше `MAX_ANALYSES_PER_RUN=8` в день, то есть максимум около $1 в день, обычно **$5–15 в месяц**. Для экономии можно поставить `CLAUDE_MODEL=claude-sonnet-5-5`, это примерно в 2 раза дешевле.

## Установка

Нужны Python 3.11+ и `ffmpeg` (`apt install ffmpeg` / `brew install ffmpeg`). Без ffmpeg разбор пойдёт только по обложке, и бот так и напишет.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить
```

### 1. Telegram
1. В @BotFather: `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. Запустите бота, напишите ему `/start`: он ответит ID чата. Впишите этот ID в `TELEGRAM_ALLOWED_CHAT_IDS` и перезапустите бота. Чужим людям бот отвечать не будет.

### 2. Instagram Graph API (бесплатно)
1. Аккаунт Instagram Welcome Travel должен быть **профессиональным** (бизнес или автор) и привязан к **странице Facebook**.
2. На [developers.facebook.com](https://developers.facebook.com) создайте приложение типа Business и добавьте продукт «Instagram» (вход через Facebook Login).
3. В [Graph API Explorer](https://developers.facebook.com/tools/explorer/) получите токен пользователя с разрешениями `instagram_basic`, `pages_show_list`, `pages_read_engagement` (и `business_management`, если страница в Business Manager). Так как приложением пользуетесь только вы, проходить App Review не нужно.
4. Обменяйте токен на долгоживущий (60 дней) или создайте **токен системного пользователя** в Business Manager (не истекает — так удобнее).
5. ID Instagram-аккаунта: запрос `me/accounts?fields=instagram_business_account` в Explorer → `instagram_business_account.id` в `IG_USER_ID`.

### 3. Claude API
Ключ на [platform.claude.com](https://platform.claude.com) → `ANTHROPIC_API_KEY`.

### 4. Аккаунты и профиль бизнеса
- `accounts.yaml` — 3–5 аккаунтов для старта, у каждого ниша (используется в разборе).
- `business_profile.md` — направления, аудитория, тон, реальные возможности съёмки. Чем точнее профиль, тем практичнее идеи.

### 5. Проверка и запуск
```bash
python scripts/check_access.py --candidates   # бесплатно: какие данные приходят и что выделяется
python -m welcome_scout                       # запустить бота
```
В боте: `/check` → `/digest` (собрать подборку сейчас). Дальше подборка приходит каждый день в `DIGEST_TIME`.

> Первый запуск: для базы сравнения нужно хотя бы 6 «созревших» публикаций того же типа. Если аккаунт публикует мало, кандидатов от него поначалу не будет — `/check` и `--candidates` это покажут.

## Команды бота
`/digest` · `/check` · `/accounts` · `/add username [ниша] [apify]` · `/remove username` · `/ideas` · `/script номер` · `/cancel` · `/help`

## Настройки отбора (`.env`)
| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DIGEST_SIZE` | 5 | максимум примеров в подборке |
| `OUTLIER_MIN_RATIO` | 3.0 | во сколько раз лучше медианы для «выброса» |
| `RISING_MIN_RATIO` / `RISING_MAX_AGE_HOURS` | 1.5 / 72 | порог «быстрого роста» для свежих публикаций |
| `MATURE_MIN_AGE_HOURS` | 48 | с какого возраста публикация считается «созревшей» |
| `LOOKBACK_DAYS` | 30 | публикации старше не предлагаются |
| `POSTS_PER_ACCOUNT` | 30 | сколько последних публикаций забирать (влияет на стоимость Apify) |
| `MAX_ANALYSES_PER_RUN` | 8 | предел разборов в день (влияет на стоимость Claude) |

## Развёртывание
Бот должен работать постоянно: подойдёт любой VPS (`systemd`/`docker`) или PaaS с постоянным процессом. Данные хранятся в `data/scout.db`. Сохраняйте этот файл между перезапусками, иначе бот забудет, что уже отправлял.
